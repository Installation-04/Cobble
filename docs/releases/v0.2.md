# Cobble v0.2 — release notes and validation report

**English** · [Français](#français)

## Status

The v0.2 code is complete, **including steps 12 and 13** (the agent runner and the previews are modules, the v0.1 pack path is retired; module images are built by CI, published to GHCR and pinned by digest). v0.2 was started before the v0.1 step 11 validation, by explicit owner decision (an override of `PLAN.md` §18). **`v0.2.0` is not published**, and neither is `v0.1.0`. Nothing here has been run on a clean VM with a real model.

### What is demonstrated

| Criterion | Evidence |
|---|---|
| Install and uninstall every official module in any order without conflict | `backend/tests/unit/test_catalog_matrix.py`: the real manifests of `catalog/`, the real module-manager with a fake Docker, every install order × every removal order, state compared with what the requested modules call for after each step, nothing left at the end; plus the resolver's property tests (`sdk/tests`) |
| Forgejo + Woodpecker plug themselves together | matrix test; live run (`make smoke-modules`) |
| The whole chain through the modules (Forgejo, Woodpecker, agents, previews) | `scripts/e2e_full.sh`: `RESULT: PASS`, 22 min, 14 tasks merged, 3 demos validated, $0.087 with the fake LLM; teardown leaves nothing behind (`docs/en/e2e-full.md`) |
| Ollama + the model gateway plug themselves together | live run: models added to the gateway, restarted, answering; CPU / NVIDIA / AMD flavours are chosen from the machine (NVIDIA and AMD **not tested on hardware**) |
| Store tab, starter packs, install / remove with live progress | `ui/src/store` tests, Playwright `store.spec.ts`, and a manual run in Chromium (light, dark, French) |
| Model connections: key entered, tested, made the default | backend tests, UI tests, `cobble models`; live: a custom service connected, key encrypted at rest and absent from logs and events, gateway health `ok`, chat answered by that model (about 20 s per change) |
| First-run wizard (machine and pack → model → example project) | `WelcomePage.test.tsx`, backend tests for `/setup/*`; **not** run in a real browser |
| Module SDK (`init`, `lint`, `test`) | `sdk/tests/test_cli.py`; `make lint` lints the official catalogue |

### Known limits

- The images of `aider` and `preview` live in GHCR under the repository owner: the packages must be public for an install without a registry login (they were public when checked). Changing anything under `services/`, `runners/aider/` or `templates/fastapi-react/` makes new digests that must be pinned again (`scripts/pin_images.py`).
- Breaking: a v0.1 pack installed by hand is no longer detected or supported; nothing is migrated.
- A module container behind a TLS-inspecting proxy has no way to receive a CA bundle (Ollama could not pull a model in the development sandbox).
- GPU flavours and real model downloads were not tested on hardware.
- Uninstall always deletes a module's data (no "keep data"); module settings and secrets cannot be edited from the UI yet.
- Third-party catalogues, custom containers, repository import, multi-node are out of scope (later versions).
- Decisions waiting for the owner: ADR 0008 (module-manager) and ADR 0009 (model connections) are proposed, not accepted.

### Before publishing

1. Validate v0.1 end to end on a clean VM with a real key, using **this** version's Settings → Models (the v0.1 protocol could not be run as written; see `docs/releases/v0.1.md`).
2. Accept ADRs 0008 and 0009; then tag `v0.1.0` and `v0.2.0`.

## Français

## Statut

Le code de la v0.2 est complet, **y compris les étapes 12 et 13** (le runner d'agents et les aperçus sont des modules, le chemin du pack v0.1 est retiré; les images des modules sont construites par la CI, publiées sur GHCR et épinglées par empreinte). La v0.2 a été commencée avant la validation de l'étape 11 de la v0.1, par décision explicite du propriétaire (dérogation à `PLAN.md` §18). **`v0.2.0` n'est pas publiée**, `v0.1.0` non plus. Rien n'a été exécuté sur une VM vierge avec un vrai modèle.

### Ce qui est démontré

| Critère | Preuve |
|---|---|
| Installer et désinstaller chaque module officiel dans n'importe quel ordre sans conflit | `backend/tests/unit/test_catalog_matrix.py` : les vrais manifestes de `catalog/`, le vrai gestionnaire de modules avec un faux Docker, tous les ordres d'installation × tous les ordres de retrait, état comparé à ce que demandent les modules choisis après chaque étape, rien ne reste à la fin; plus les tests de propriétés du résolveur (`sdk/tests`) |
| Forgejo + Woodpecker se branchent seuls | test de matrice; exécution réelle (`make smoke-modules`) |
| Toute la chaîne par les modules (Forgejo, Woodpecker, agents, aperçus) | `scripts/e2e_full.sh` : `RESULT: PASS`, 22 min, 14 tâches fusionnées, 3 démos validées, 0,087 $ avec le faux LLM ; le démontage ne laisse rien (`docs/fr/e2e-full.md`) |
| Ollama + la passerelle de modèles se branchent seuls | exécution réelle : modèles ajoutés à la passerelle, redémarrée, qui répond; les variantes CPU / NVIDIA / AMD sont choisies selon la machine (NVIDIA et AMD **non testées sur du matériel**) |
| Onglet Magasin, packs de départ, installation / retrait avec progression en direct | tests `ui/src/store`, Playwright `store.spec.ts`, essai manuel dans Chromium (clair, sombre, français) |
| Connexions de modèles : clé saisie, testée, mise par défaut | tests backend et UI, `cobble models`; en réel : un service personnalisé connecté, clé chiffrée au repos et absente des journaux et événements, santé de la passerelle `ok`, conversation répondue par ce modèle (environ 20 s par changement) |
| Assistant de premier lancement (machine et pack → modèle → projet d'exemple) | `WelcomePage.test.tsx`, tests backend de `/setup/*`; **pas** essayé dans un vrai navigateur |

### Limites connues

- Les images de `aider` et `preview` sont sur GHCR sous le propriétaire du dépôt : les paquets doivent être publics pour une installation sans connexion au registre (ils l'étaient à la vérification). Toute modification sous `services/`, `runners/aider/` ou `templates/fastapi-react/` produit de nouvelles empreintes à épingler de nouveau (`scripts/pin_images.py`).
- Rupture : un pack v0.1 installé à la main n'est plus détecté ni pris en charge ; rien n'est migré.
- Un conteneur de module derrière un proxy qui inspecte TLS ne peut pas recevoir de bundle de CA (Ollama n'a pas pu télécharger de modèle dans le bac à sable de développement).
- Les variantes GPU et les vrais téléchargements de modèles n'ont pas été testés sur du matériel.
- La désinstallation supprime toujours les données d'un module (pas de « garder les données »); les réglages et secrets des modules ne sont pas encore modifiables depuis l'interface.
- Catalogues tiers, conteneurs personnalisés, import de dépôt, multi-nœud : hors périmètre (versions suivantes).
- Décisions en attente du propriétaire : les ADR 0008 (gestionnaire de modules) et 0009 (connexions de modèles) sont proposés, pas acceptés.

### Avant de publier

1. Valider la v0.1 de bout en bout sur une VM vierge avec une vraie clé, avec Réglages → Modèles de **cette** version (le protocole v0.1 ne pouvait pas être suivi tel qu'écrit; voir `docs/releases/v0.1.md`).
2. Accepter les ADR 0008 et 0009; puis étiqueter `v0.1.0` et `v0.2.0`.
