# Cobble v0.3 — release notes and validation report

**English** · [Français](#français)

## Status

The v0.3 features of the plan are **written and tested**; the v0.3 acceptance criterion is **not met yet**: it asks for a measured run of 5 reference projects with real models, which needs an API key that only the owner provides (`PLAN.md` §14, `CLAUDE.md`). Everything needed for that run is in the repository (`make bench`), and nothing has been run against a real model.

### What is delivered

| Item (`PLAN.md` §14 / §17) | What it is | Evidence |
|---|---|---|
| Role routes, fallback chains, escalation | Per-role model chains; a call falls back on key/balance/rate-limit/unknown-model/service errors and the fallback is recorded | ADR 0010, `test_role_routes.py`, Costs tab |
| Model presets | "Economical local" and "Balanced" fill the routes in one click | ADR 0010, `test_presets.py`, Settings → Models |
| Local model benchmark | 8 coding tasks with hidden cases, code run in a sandbox with no network; proposes the best `worker`; from the CLI or Settings | ADR 0012, 0019, `test_benchmark*.py` |
| Savings counter, project report | Real cost against doing everything with the strongest model; per-project report (JSON and Markdown, FR/EN) | ADR 0010, 0014 |
| "Local only" projects | No call may reach a model that is not served on this machine; fails closed | ADR 0011 |
| Up-to-date prices, free tiers | Last price seen per model, change warning, free badge, 429 back-off | ADR 0013 |
| Electricity, per-task budget, model-aware estimate | Estimated electricity of local models; a task cap (default 3x its estimate); estimate priced per role | ADR 0021 |
| Crash recovery | Planner answers checkpointed; crashing jobs dead-lettered; no stealing between workers; orphan runs adopted | ADR 0016 |
| Reviewer agent, task time limit | Optional review before merge; 45 min per task by default | ADR 0024 |
| Questions to the human | An agent stops and asks; no tokens while waiting | ADR 0025 |
| Lessons learned | Per-project lessons captured from failures and injected into later prompts | ADR 0026 |
| Explain mode, mockup variants | Plain-language summary per milestone; 2 to 3 wireframes to choose from before planning | ADR 0017, 0018 |
| Package caches | Verdaccio and devpi modules, wired to the agent runners when installed | ADR 0015, 0027 |
| 5 reference projects and `make bench` | Frozen FR/EN specs, hidden tests validated against reference solutions and mutation-checked; runner with a dry-run mode | ADR 0020, `make bench-check` |
| Install from GitHub | One command from the repository; release pipeline publishing the core images by digest | ADR 0022, 0023 |

Tests at the time of writing: backend 1702, UI 266, SDK 185, agent-service 70, installer 24, plus the migration tests (0010 to 0021, up and down, with the model-drift check) on a real Postgres.

### Known limits

- **No real-model run.** Success rate and average cost on real models are unmeasured, and "no agent exceeds its budget" is only exercised on the simulator. A call already in flight can still overshoot a budget by one call.
- **Never run for real:** the release workflow, the verdaccio and devpi images, the Aider entrypoint's question protocol, Redis stream recovery (tested on an in-memory fake), the new screens in a browser (Playwright e2e passes on the existing flows).
- **No release exists yet:** the one-line install fails with a clear message until the first tag; GHCR packages start private and must be made public once.
- The reviewer call runs inside the scheduler tick, so a slow model delays that tick for all projects. When changes are requested and no attempt is left, the task is merged with a warning rather than failed.
- Lesson capture was tested on log shapes written in the tests, not on real CI output.
- Out of scope (later versions): live iframe preview (issue labelled `idée`), custom containers, third-party catalogues, multi-node.
- Decisions waiting for the owner: ADRs 0008 to 0027 are proposed (0008 is a draft), none accepted yet.

### Before publishing

1. Provide an API key and run `make bench` once with real models (`docs/en/bench.md`); publish the success rate and average cost.
2. Validate v0.1 on a clean VM with a real key (see `docs/releases/v0.1.md`).
3. Pin the module image digests (`images.yml`, `scripts/pin_images.py`), accept the ADRs, then tag and follow `docs/en/releasing.md`.

## Français

## Statut

Les fonctions de la v0.3 prévues au plan sont **écrites et testées**; le critère d'acceptation de la v0.3 **n'est pas encore atteint**: il demande une mesure sur 5 projets de référence avec de vrais modèles, ce qui exige une clé d'API que seul le propriétaire fournit (`PLAN.md` §14, `CLAUDE.md`). Tout ce qu'il faut pour cette mesure est dans le dépôt (`make bench`), et rien n'a été lancé contre un vrai modèle.

### Ce qui est livré

| Élément (`PLAN.md` §14 / §17) | De quoi il s'agit | Preuve |
|---|---|---|
| Routes par rôle, chaînes de repli, escalade | Chaînes de modèles par rôle; un appel bascule sur une erreur de clé, de solde, de limite, de modèle inconnu ou de service, et le repli est enregistré | ADR 0010, `test_role_routes.py`, onglet Coûts |
| Préréglages de modèles | « Économique local » et « Équilibré » remplissent les routes en un clic | ADR 0010, `test_presets.py`, Réglages → Modèles |
| Benchmark de modèles locaux | 8 tâches de code avec cas cachés, code exécuté dans un bac à sable sans réseau; propose le meilleur `worker`; en CLI ou depuis les Réglages | ADR 0012, 0019, `test_benchmark*.py` |
| Compteur d'économies, rapport de projet | Coût réel contre tout faire avec le modèle le plus fort; rapport par projet (JSON et Markdown, FR/EN) | ADR 0010, 0014 |
| Projets « local seulement » | Aucun appel ne peut atteindre un modèle qui n'est pas servi sur cette machine; échec fermé | ADR 0011 |
| Prix à jour, paliers gratuits | Dernier prix vu par modèle, avertissement de changement, badge gratuit, attente après un 429 | ADR 0013 |
| Électricité, budget par tâche, estimation par modèle | Électricité estimée des modèles locaux; plafond par tâche (3 fois son estimation par défaut); estimation chiffrée par rôle | ADR 0021 |
| Reprise après panne | Réponses du planificateur enregistrées; tâches qui plantent mises de côté; plus de vol entre workers; runs orphelins adoptés | ADR 0016 |
| Agent réviseur, durée maximale d'une tâche | Relecture optionnelle avant la fusion; 45 min par tâche par défaut | ADR 0024 |
| Questions à l'humain | Un agent s'arrête et demande; aucun jeton pendant l'attente | ADR 0025 |
| Leçons apprises | Leçons par projet tirées des échecs et injectées dans les prompts suivants | ADR 0026 |
| Mode « Explique-moi », variantes de maquette | Résumé en langage simple par jalon; 2 à 3 wireframes à choisir avant la planification | ADR 0017, 0018 |
| Caches de paquets | Modules Verdaccio et devpi, branchés aux runners d'agents quand ils sont installés | ADR 0015, 0027 |
| 5 projets de référence et `make bench` | Specs FR/EN figées, tests cachés validés contre des solutions de référence et par mutations; exécuteur avec mode à blanc | ADR 0020, `make bench-check` |
| Installation depuis GitHub | Une commande depuis le dépôt; pipeline de publication des images du noyau par digest | ADR 0022, 0023 |

Tests au moment de la rédaction: backend 1702, UI 266, SDK 185, agent-service 70, installateur 24, plus les tests de migration (0010 à 0021, montée et descente, avec la vérification de dérive des modèles) sur un vrai Postgres.

### Limites connues

- **Aucun run avec un vrai modèle.** Le taux de réussite et le coût moyen sur de vrais modèles ne sont pas mesurés, et « aucun agent ne dépasse son budget » n'est éprouvé que sur le simulateur. Un appel déjà en cours peut encore dépasser un budget d'un appel.
- **Jamais exécutés pour de vrai:** le workflow de publication, les images verdaccio et devpi, le protocole de question de l'entrypoint Aider, la reprise des flux Redis (testée sur un faux en mémoire), les nouveaux écrans dans un navigateur (l'e2e Playwright passe sur les parcours existants).
- **Aucune release n'existe encore:** l'installation en une commande échoue avec un message clair jusqu'au premier tag; les paquets GHCR naissent privés et doivent être rendus publics une fois.
- L'appel du réviseur se fait dans le cycle du scheduler, donc un modèle lent retarde ce cycle pour tous les projets. Quand des changements sont demandés et qu'il ne reste plus d'essai, la tâche est fusionnée avec un avertissement au lieu d'échouer.
- La capture de leçons a été testée sur des formes de journaux écrites dans les tests, pas sur de vraies sorties de CI.
- Hors portée (versions ultérieures): aperçu iframe en direct (issue étiquetée `idée`), conteneurs personnalisés, catalogues tiers, multi-nœuds.
- Décisions en attente du propriétaire: les ADR 0008 à 0027 sont proposés (le 0008 est un brouillon), aucun n'est encore accepté.

### Avant de publier

1. Fournir une clé d'API et lancer `make bench` une fois avec de vrais modèles (`docs/fr/bench.md`); publier le taux de réussite et le coût moyen.
2. Valider la v0.1 sur une VM vierge avec une vraie clé (voir `docs/releases/v0.1.md`).
3. Épingler les digests des images des modules (`images.yml`, `scripts/pin_images.py`), accepter les ADR, puis taguer en suivant `docs/fr/releasing.md`.
